**How do I set up Grok to trade for me?** Give a Grok-based agent the Sherwood skill and the Sherwood MCP server or CLI, and connect it to a sign-only agent wallet such as the MetaMask Agent Wallet or Privy. The agent researches, sizes and prepares each proposal as unsigned transactions, and you approve every transaction that moves funds before the wallet signs it. Your vault's caps, the depositor vote and guardian review all apply before any capital is deployed.

Sherwood does not depend on a particular model. It is a skill pack, a CLI, an HTTP API and an MCP server that sit on top of the agent you already run. Grok is the model; the runtime is whatever hosts it and gives it tools. The steps below are the same for any agent, except the model attestation at the end.

<Steps>
  <Step title="Pick a runtime for your Grok agent">
    This step happens outside the Sherwood CLI. Use any agent runtime that can call a Grok model and either connect to a remote MCP server or run shell commands. The agent needs one of these to read vault state and prepare transactions:

    - **MCP only.** The agent connects to the hosted MCP server and never installs anything. This covers reads and every `prepare_*` transaction.
    - **MCP plus CLI.** The agent can also run shell commands. Add the CLI for what the MCP server does not cover: cohort chat, data feed login, paid research and strategy template encoding (`strategy propose`).

    On the [Hermes agent runtime](https://github.com/NousResearch/hermes-agent), a companion plugin adds event streaming, cron digests and risk guardrails (next step).
  </Step>

  <Step title="Give the agent the Sherwood skill">
    This step happens in your runtime, not in the CLI. Load the Sherwood skill pack from [github.com/sherwoodagent/skill](https://github.com/sherwoodagent/skill) into the agent's instructions or skills folder, following your runtime's own way of adding skills. `SKILL.md` is the entry point; it teaches the commands, the launch rules and the "Ask before funds move" rule, and the `references/` and `skills/` folders cover the vault owner, guardian and strategy roles.
  </Step>

  <Step title="Connect the Sherwood MCP server">
    Point the agent's MCP client at the hosted server. It has no auth and holds no keys:

    ```text
    https://mcp.sherwood.sh/mcp
    ```

    The server has 67 tools in three groups: util, read (`get_*`, `list_*`, `check_*`) and prepare (`prepare_*`). Have the agent call `get_started` first; with a `topic` such as `create_vault` or `propose` it returns the multi-tool flow. The `prepare_*` tools return unsigned `{ to, data, value, chainId }` transactions and never sign or send. Client configs for Claude Code, Cursor, VS Code, Codex and others are on the MCP page. The skill repo also ships a `.mcp.json` with the same URL.

    - [MCP server](/api/mcp)
    - [HTTP API](/api/overview)
  </Step>

  <Step title="Install the CLI (if the agent runs shell commands)">
    Install the pinned CLI globally, with Node.js 22 or later. Install it with `npm i -g`, not through `npx`, because chat needs the pinned XMTP build:

    ```bash
    npm install -g @sherwoodagent/cli@0.96.0
    sherwood --version
    ```

    On Hermes, also install the plugin:

    ```bash
    hermes plugins install sherwoodagent/sherwood-hermes-plugin@v0.6.0
    ```

    - [CLI installation](/cli/installation)
    - [Cron jobs](/cli/cron-jobs)
  </Step>

  <Step title="Give the agent a sign-only wallet">
    Keep keys out of the model's reach. Use the **MetaMask Agent Wallet** first, once `mm chains list` shows Robinhood Chain (4663); **Privy** is the second option and works either way. The agent prepares transactions (with `prepare_*` tools or the root `--calldata-only` flag), and the wallet signs and broadcasts them in order, waiting for each receipt before the next.

    Before fund setup, set the wallet policy: allowlist the Sherwood core contracts, then your vault and governor after `vault create`, and size the rolling 24-hour outflow cap for the whole setup, approvals included. Anything outside the policy is held for a human to approve, by email for MetaMask. Never switch to an unguarded mode to avoid those emails.

    - [External signer](/cli/external-signer): setup, the sign-then-broadcast loop, and the Privy recipe
    - [Deployments](/reference/deployments): contract addresses for the allowlist
  </Step>

  <Step title="Set the agent's rules">
    This step happens in your agent's system prompt or runtime config, not in the CLI. Tell the agent to:

    - Ask you before any transaction that pays, approves, stakes, bonds or deposits: buying WOOD, the creation fee, the owner stake, every proposer bond, deposits and paid research. It shows the amount, the token and the wallet, and waits for an explicit yes. `--yes` only skips the CLI's own prompt.
    - Quote the live proposer bond before every proposal, never a fixed WOOD figure.
    - Never raise `minBufferBps` while a proposal is open.
    - Stop and report if any transaction in a batch reverts, instead of sending the rest.

    - [Getting started](/guides/getting-started): the "Ask before funds move" rule
    - [Proposer bond](/explanations/proposer-bond)
  </Step>

  <Step title="Mint an identity and create the fund">
    Follow [Getting started](/guides/getting-started) from the sponsorship check through the first settled proposal. At launch, vault creation is sponsored only for the exact wallet the waitlist approved, so the agent's signing wallet must be that wallet, and it must own the ERC-8004 identity:

    ```bash
    sherwood --calldata-only identity mint --name "My Grok Agent"
    ```

    Read the token id from the mint receipt's `Transfer` event and pass it as `--agent-id` from then on. The MCP equivalent is `prepare_identity_mint`.

    - [Launch posture](/explanations/launch-posture)
    - [Owner stake](/explanations/owner-stake)
    - [ERC-8004](/reference/integrations/erc-8004)
  </Step>

  <Step title="Record the model version on chain">
    Attest the model and prompt configuration, and attest again on every change, so depositors can tie the track record to a model version:

    ```bash
    sherwood --calldata-only attest version \
      --agent-id $AGENT_ID \
      --agent $ME \
      --model-config ./model-config.json \
      --label "grok-4 / prompt v7"
    ```

    `--agent` (the signing wallet) is required with `--calldata-only`. The CLI attests the canonical keccak256 of the JSON file, not its contents, so the config itself stays private. The attestation is public and permanent.

    - [EAS attestations](/reference/integrations/eas)
  </Step>

  <Step title="Run the fund">
    Hand the agent the proposal loop: private management plan, sizing against the caps, timing around the feeds, propose, vote and guardian review, execute, settle and reclaim the bond. You approve each transaction that moves funds.

    - [Run a fund](/guides/run-a-fund)
  </Step>
</Steps>
