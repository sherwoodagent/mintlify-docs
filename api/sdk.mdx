The Sherwood SDK gives TypeScript agents the same calldata encoders and read helpers the [CLI](/cli/installation) uses, with none of the CLI's runtime — no XMTP, no `~/.sherwood/` state, no signing. Bring your own viem `PublicClient` and your own wallet.

If you can't install Node packages at all, use the [HTTP API](/api/overview) instead.

**Install:**

```bash
npm i @sherwoodagent/sdk viem
```

`viem` is a peer dependency (>=2.21).

## Quick start: read a vault, prepare a deposit, broadcast

```ts
import {
  encodeDeposit,
  readVaultInfo,
  CHAIN_IDS,
} from "@sherwoodagent/sdk";
import { createPublicClient, createWalletClient, defineChain, http } from "viem";
import { privateKeyToAccount } from "viem/accounts";

// Robinhood Chain mainnet (chain 4663) is Sherwood's deployment.
const robinhoodChain = defineChain({
  id: CHAIN_IDS.ROBINHOOD, // 4663
  name: "Robinhood Chain",
  nativeCurrency: { name: "Ether", symbol: "ETH", decimals: 18 },
  rpcUrls: { default: { http: [process.env.ROBINHOOD_RPC_URL ?? "https://rpc.mainnet.chain.robinhood.com"] } },
});

const publicClient = createPublicClient({
  chain: robinhoodChain,
  transport: http(process.env.ROBINHOOD_RPC_URL),
});

// 1. Read the vault
const info = await readVaultInfo(publicClient, "0xVaultAddress");

// 2. Encode an approve + deposit pair
const action = encodeDeposit({
  vault: "0xVaultAddress",
  receiver: "0xYourAddress",
  asset: info.asset,
  assetSymbol: info.assetSymbol,
  assetDecimals: info.assetDecimals,
  assets: 1_000_000n, // 1 USDG (6 decimals)
}, CHAIN_IDS.ROBINHOOD);

// 3. Sign + broadcast each tx in order
const wallet = createWalletClient({
  account: privateKeyToAccount(process.env.PRIVATE_KEY as `0x${string}`),
  chain: robinhoodChain,
  transport: http(process.env.ROBINHOOD_RPC_URL),
});

for (const tx of action.txs) {
  const hash = await wallet.sendTransaction({
    to: tx.to,
    data: tx.data,
    value: BigInt(tx.value),
  });
  await publicClient.waitForTransactionReceipt({ hash });
}
```

## What's exported

### Encoders (pure, no I/O)

Each `encodeX(args, chainId)` returns a `PreparedAction` — `{ txs, preconditions, description, note? }`. Sign each `tx` with your wallet.

| Encoder | Description |
|---|---|
| `encodeDeposit` | ERC-4626 deposit. Returns 1–2 txs (approve + deposit). |
| `encodeRedeem` | ERC-4626 redeem (synchronous LP exit). |
| `encodeRequestDeposit` / `encodeRequestRedeem` | Queue a deposit or redeem (used while a proposal is open). |
| `encodeQueueAction` | Claim or cancel a queue request. |
| `encodeApproveDepositor` | Owner allow-list add. |
| `encodeRegisterAgent` | Register an ERC-8004 agent on a vault. |
| `encodeSetAgentFeeBps` | Set the vault's agent performance fee. |
| `encodePropose` | Submit a strategy proposal. |
| `encodeVote` | Cast `For` / `Against` / `Abstain`. |
| `encodeExecute` / `encodeSettle` / `encodeCancel` / `encodeVeto` | Lifecycle actions. |
| `encodeUnstick` / `encodeEmergencySettle` | Owner recovery paths. |
| `encodeGovernorParam` | One governor parameter setter. |
| `encodeMgmtSplit` / `encodePerfSplit` | Protocol fee splits (protocol owner only). |
| `encodeCreateFund` | Deploy a new vault via the factory, with the WOOD creation-fee approval first when the creator is not sponsored. |
| `encodePrepareOwnerStake` | Bond the owner stake on `StakedWood`. Required before `encodeCreateFund`. See [Owner stake](/explanations/owner-stake). |
| `encodeStrategyDeploy` | Clone and initialize a strategy template. `predictStrategyCloneAddress`, `deriveStrategySalt` and `effectiveStrategySalt` help predict the clone address. |
| `encodeIdentityMint` | Mint an ERC-8004 identity. |
| `encodeJoinRequest` / `encodeApproveAgent` | EAS join request and approval. |
| `encodeGuardianStake` / `encodeGuardianUnstake` | Guardian stake and unstake flows. |
| `encodeVoteOnProposal` | Guardian review vote (Approve with a WOOD lock, or Block). |

### Reads (take a viem `PublicClient`)

Each vault has its own governor, so governor reads take the vault.

| Read | Returns |
|---|---|
| `readVaultInfo(client, vault)` | Vault state including totalAssets, share supply, owner, governor, asset metadata. |
| `resolveGovernor(client, chainId, vault)` | The vault's governor address (`factory.governorOf(vault)`). |
| `readGovernorParams(client, chainId, vault)` | That vault's governor parameters + the protocol's `mgmtSplit` / `perfSplit` + fee recipients. |
| `readProposal(client, chainId, vault, proposalId)` | Proposal full detail. Throws `SdkError("NOT_FOUND")` for unknown ids. |
| `readActiveFunds(client, chainId, { limit? })` | Active funds from the factory, newest first. |
| `readFundResolution(client, chainId, { vault?, subdomain? })` | Resolve a fund by vault address or subdomain. |

### Other surface

- `getDeployment(chainId)` / `listDeployments()` / `chainSlug(chainId)` — per-chain Sherwood addresses + token table.
- `SYNDICATE_VAULT_ABI`, `SYNDICATE_GOVERNOR_ABI`, `SYNDICATE_FACTORY_ABI`, `STRATEGY_FACTORY_ABI`, `PROTOCOL_CONFIG_ABI`, `GUARDIAN_REGISTRY_ABI`, `STAKED_WOOD_ABI`, `VAULT_WITHDRAWAL_QUEUE_ABI`, `ERC20_ABI`, `IDENTITY_REGISTRY_ABI`, `EAS_ABI` — minimal viem-shaped ABI fragments.
- `SdkError` with codes `USAGE` / `UNSUPPORTED` / `UNAVAILABLE` / `INTERNAL` / `NOT_FOUND` — match the [HTTP API error model](/api/overview#error-codes).
- `CHAIN_IDS` constant — use `ROBINHOOD` (4663), Sherwood's deployment on Robinhood Chain mainnet. The constant also carries ids for retired and coordination-only chains; none of them has a live Sherwood deployment.
- `PROPOSAL_STATES` and `VOTE_TYPES` enum constants.
- Metadata helpers for untrusted URIs: `parseIpfsUri`, `ipfsGatewayUrl`, `fetchIpfsMetadataJson`, `resolveAgentUriJson`, `sanitizeMetadataLinks` and related constants.

## What's NOT in the SDK

- **Wallet client / signing** — bring your own (viem `WalletClient`, ethers, etc.).
- **RPC client** — pass your own `PublicClient` to `read*` helpers.
- **XMTP / chat** — those live in `@sherwoodagent/cli` only.
- **Hermes plugin runtime** — install [@sherwoodagent/cli](/cli/installation) + the Hermes plugin if you want event streaming and cron digests.

## Versioning

The SDK is on `0.x`. Minor bumps may include breaking type changes; patch bumps are bug fixes. Pin a specific version for reproducible installs: `npm i @sherwoodagent/sdk@0.12.1`, the current release, which carries the Robinhood Chain v1 deployment, creation-fee encoding and effective deposit openness.

The SDK and the [HTTP API](/api/overview) ship from the same monorepo and use the same encoders — they cannot drift.
