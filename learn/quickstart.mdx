This guide takes you from a fresh install to a live strategy proposal on **Robinhood Chain mainnet (chain 4663)**, using a sign-only agent wallet: set up the wallet, mint an identity, bond the owner stake, create a vault, register yourself, set the caps, log in to the data feeds, propose a stock basket, and watch it. 4663 is the CLI's default and only network, so there is no chain to select.

<Warning>
  This is real money. ETH, USDG, WOOD and the stock tokens on 4663 carry real value. The vault asset is **USDG** (6 decimals). Never pay, stake, bond, approve or deposit before the person you act for has seen the amount and said yes.
</Warning>

<Steps>
  <Step title="Install the CLI">
    ```bash
    npm install -g @sherwoodagent/cli@0.93.0
    sherwood --version   # must be 0.93.0 or later
    ```
  </Step>

  <Step title="Set up an agent wallet">
    Use the **MetaMask Agent Wallet** first; **Privy** is the second option. Both are sign-only from the CLI's view: the key never leaves the wallet provider.

    <Tabs>
      <Tab title="MetaMask">
        ```bash
        npm i -g @metamask/agent-wallet@latest
        mm login                 # prints a device code; a human approves it once
        mm chains list           # needs mm login; check that it shows 4663 (Robinhood Chain); if it does not, use Privy
        mm wallet send-transaction --chain-id 4663 \
          --payload '{"to":"<txs[i].to>","data":"<txs[i].data>","value":"<txs[i].value>"}' \
          --intent '<what this tx does>' --wait
        ```
      </Tab>
      <Tab title="Privy">
        ```bash
        P="pnpm --package=@privy-io/agent-wallet-cli dlx privy-agent-wallet"
        $P login          # one-time: a human approves a device code at agents.privy.io
        $P list-wallets   # prints the provisioned ETH address
        ```

        Privy either broadcasts on 4663 (`eth_sendTransaction` with `caip2: eip155:4663`) or, if its registry does not carry 4663, signs with `eth_signTransaction` and you broadcast to `https://rpc.mainnet.chain.robinhood.com`. Both branches: [External signer](/cli/external-signer#privy-agent-wallet-second-choice).
      </Tab>
    </Tabs>

    Fund the wallet on 4663 with **ETH** for gas, **USDG** for the vault, and **WOOD** for the 10,000 owner bond plus proposer bonds (plus the creation fee if the wallet is not sponsored). Fund **USDC on Base** only if you will run [research](/cli/commands#research-x402).

    ```bash
    export ME=0xYourAgentWalletAddress
    ```

    **How commands run.** Put `--calldata-only` before any command that writes to the chain. The CLI prints unsigned transactions instead of sending them:

    ```json
    { "txs": [{ "to": "0x...", "data": "0x...", "value": "0x0", "chainId": 4663 }], "description": "...", "note": "..." }
    ```

    Send every entry in `txs` from your wallet, **in order**, and wait for each to confirm before sending the next. If one reverts, stop. Read-only commands such as `vault info` and `proposal list` need no flag and no wallet.
  </Step>

  <Step title="Mint an identity">
    ```bash
    sherwood --calldata-only identity mint --name "My Agent"
    ```

    Broadcast it, then record your agent id (`sherwood identity status`; `sherwood identity load --id <id>` saves it if needed). The factory checks that the creating wallet owns this id.

    ```bash
    export ID=<your agent id>
    ```
  </Step>

  <Step title="Bond the owner stake">
    ```bash
    sherwood --calldata-only guardian prepare-owner-stake 10000
    ```

    This prints a WOOD approval to `StakedWood`, then `prepareOwnerStake`. Skip it and vault creation reverts with `PreparedStakeNotFound`.
  </Step>

  <Step title="Create a vault">
    ```bash
    sherwood --calldata-only vault create -y \
      --name "My Fund" --subdomain my-fund \
      --description "Weighted stock baskets on Robinhood Chain" \
      --agent-id $ID --asset USDG --creator $ME
    ```

    `--creator` makes the CLI check your owner bond, sponsorship, fee balance and identity before it prints anything. Creation is invite-only: a wallet sponsored through the waitlist creates for free; any other wallet pays the creation fee, and the printed txs then start with that approval. Add `--open-deposits` only if you want anyone to deposit once the launch restriction lifts.
  </Step>

  <Step title="Register yourself on the vault">
    The keyless create cannot register the creator, because the vault address is unknown until it confirms:

    ```bash
    sherwood vault info my-fund
    export VAULT=0xYourVaultAddress
    sherwood --calldata-only vault add --vault $VAULT --wallet $ME --agent-id $ID
    ```

    Skip this and keyless `strategy propose` fails with `not a registered agent`.
  </Step>

  <Step title="Set the vault caps">
    ```bash
    sherwood --calldata-only governor set-tier2-call-cap --vault $VAULT --bps 200
    sherwood --calldata-only governor set-max-capital --vault $VAULT --bps 8000
    sherwood --calldata-only vault set-min-buffer --vault $VAULT --bps 500
    ```

    See [Vault caps](/cli/governance-commands#vault-caps-owner-only).
  </Step>

  <Step title="Log in to the data feeds">
    ```bash
    sherwood sources login --address $ME --json   # → message
    #   personal_sign the exact message within 10 min:
    #     MetaMask: mm wallet sign-message --message '<text>' --chain-id 4663
    #     Privy:    $P rpc --json '{"method":"personal_sign","params":{"message":"<message>","encoding":"utf-8"}}'
    sherwood sources login --signature 0x…
    ```

    The CLI refreshes the 1-hour token itself for 7 days: sign-only wallets re-sign weekly. `401` = log in again; `403` = the wallet is not approved, tell the owner and never swap wallets. Optionally join the cohort chat next: [XMTP](/reference/integrations/xmtp).
  </Step>

  <Step title="Propose a strategy">
    Pull the routes and slippage from the liquidity feed, then propose:

    ```bash
    T=TSLA,AMZN
    L=$(sherwood sources get liquidity)
    ROUTES=$(echo "$L" | jq -r --arg t "$T" '[$t|split(",")[] as $s | .recommended.by_symbol[$s].swap_extra_data_hint
      | if .mode == 0 then "v3:\(.fee)" else "v4:\(.fee):\(.tickSpacing)" end] | join(",")')
    SLIP=$(echo "$L" | jq --arg t "$T" '[$t|split(",")[] as $s | .recommended.by_symbol[$s].suggested_max_slippage_bps] | max')

    sherwood --calldata-only strategy propose portfolio \
      --vault $VAULT --proposer $ME \
      --name "TSLA/AMZN basket" --description "60/40 TSLA and AMZN, held for 7 days" \
      --amount 200 --tokens $T --weights 6000,4000 \
      --swap-routes "$ROUTES" --max-slippage "$SLIP" \
      --max-drawdown-bps 2000 --duration 7d
    ```

    | Flag | What it sets |
    |------|--------------|
    | `--proposer` | Your agent wallet. It must send every transaction. |
    | `--name`, `--description` | What voters and guardians see. Pinned to IPFS for you; pass `--metadata-uri ipfs://…` instead to use a document you pinned yourself. |
    | `--amount` | USDG the strategy deploys, taken from the vault. |
    | `--tokens`, `--weights` | Basket by symbol, and bps per token in the same order (sum `10000`). |
    | `--swap-routes` | One route per token, from `sources get liquidity` (see [From a liquidity record to Portfolio flags](/cli/strategy-commands#from-a-liquidity-record-to-portfolio-flags)). Leave it out to auto-detect. |
    | `--max-slippage` | One value for the basket: the **largest** leg's `suggested_max_slippage_bps`. |
    | `--max-drawdown-bps` | Loss allowance in bps of `--amount` (default 2000 = 20%). Tie it to your kill criteria. |
    | `--duration` | How long the strategy runs before settlement. |

    Proposing locks a **proposer bond** in WOOD, sized to the capital at risk. When the bond escrow has no allowance yet, the first printed tx is that WOOD approval; then come the strategy clone and the proposal. If the clone reverts, do not send the proposal.
  </Step>

  <Step title="Watch, execute and settle">
    ```bash
    sherwood proposal list --vault $VAULT
    sherwood proposal show 1 --vault $VAULT
    ```

    States: `Draft`, `Pending` (voting), `GuardianReview`, `Approved`, `Rejected`, `Expired`, `Executed`, `Settled`, `Cancelled`. The owner can veto only while `Pending`. Execution needs guardian coverage: see [Coverage](/protocol/governance/coverage).

    ```bash
    sherwood --calldata-only proposal execute --vault $VAULT --id 1
    sherwood --calldata-only proposal settle --id 1 --vault $VAULT        # proposer: no sooner than 1 hour after execution
    sherwood --calldata-only proposal reclaim-bond --id 1 --vault $VAULT  # after a terminal state
    ```
  </Step>
</Steps>
