title: "Quickstart"

This quickstart starts with read-only commands. Add a signing wallet only when you are ready to submit a testnet transaction.

## What you need

- Node.js 20 or newer
- A wallet funded with testnet ETH for gas
- Access to a fund that accepts your deposit, or an owner who can approve you

<Steps>
  <Step title="Install the CLI">
    Install the latest published release and confirm that the binary is available.

    ```bash
    npm install -g @sherwoodagent/cli@latest
    sherwood --version
    ```
  </Step>

  <Step title="Confirm the network">
    Sherwood currently exposes one network in the CLI.

    ```bash
    sherwood config show
    ```

    The output should identify `robinhood-testnet`, chain ID `46630`.
  </Step>

  <Step title="List and inspect funds">
    These commands do not require a private key.

    ```bash
    sherwood fund list
    sherwood fund info <fund-id-or-name>
    ```

    Record the vault address and check whether deposits are open or restricted.
  </Step>

  <Step title="Configure a signing wallet">
    For a temporary shell session, prefer an environment variable so the key is not written to Sherwood's config file.

    <Tabs>
      <Tab title="macOS or Linux">
        ```bash
        export PRIVATE_KEY=0x...
        ```
      </Tab>
      <Tab title="PowerShell">
        ```powershell
        $env:PRIVATE_KEY = "0x..."
        ```
      </Tab>
    </Tabs>

    Never use a production wallet or commit a private key to a file.
  </Step>

  <Step title="Set a default vault">
    Save the vault address so later commands can omit `--vault`.

    ```bash
    sherwood config set --vault <vault-address>
    sherwood vault info
    ```
  </Step>

  <Step title="Deposit testnet ETH into a WETH vault">
    Run this only if the fund accepts your address and no proposal is active.

    ```bash
    sherwood vault deposit --amount 0.01 --use-eth
    sherwood vault balance
    ```

    `--use-eth` wraps testnet ETH into the WETH asset used by the current vault before depositing. During an active proposal, use the asynchronous queue described in [vault liquidity](/protocol/vault-liquidity).
  </Step>
</Steps>
