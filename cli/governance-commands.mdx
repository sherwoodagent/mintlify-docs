---
title: "Governance commands"
description: "Create, inspect, vote on, execute, and settle per-fund proposals."
---

Proposal IDs repeat across funds. Include `--vault` in scripts and logs even when a default vault is configured.

## Inspect governance

```bash
sherwood governor info --vault 0x...
sherwood proposal list --vault 0x...
sherwood proposal show --vault 0x... <proposal-id>
```

`governor info` is the correct source for current voting periods, veto threshold, execution window, fee cap, duration cap, and cooldown.

## Create a raw proposal

Use a JSON file for each call array:

```json
[
  {
    "target": "0x0000000000000000000000000000000000000000",
    "value": "0",
    "data": "0x"
  }
]
```

Then submit the proposal:

```bash
sherwood proposal create \
  --vault 0x... \
  --name "Proposal name" \
  --description "Mechanism, risk, and settlement assumptions" \
  --duration 24h \
  --execute-calls ./execute.json \
  --settle-calls ./settle.json \
  --simulate
```

<Warning>
  `--force` allows submission after a failed requested simulation. Use it only when you can explain the simulation failure and independently verify that it does not apply onchain.
</Warning>

For Portfolio, prefer `sherwood strategy propose portfolio`, which builds the template-specific call arrays.

## Vote

```bash
sherwood proposal vote \
  --vault 0x... \
  --id <proposal-id> \
  --support against
```

Valid choices are `for`, `against`, and `abstain`. Because governance is optimistic, only `against` voting power contributes to the veto threshold.

## Execute

Simulate first:

```bash
sherwood proposal execute --vault 0x... --id <proposal-id> --dry-run
```

Then submit within the execution window:

```bash
sherwood proposal execute --vault 0x... --id <proposal-id>
```

The proposal must have cleared voting and guardian review.

## Settle

```bash
sherwood proposal settle --vault 0x... --id <proposal-id>
```

The proposer can settle after the anti-skim floor. Any caller can settle after the full strategy duration. Read [settlement](../protocol/governance/settlement.mdx) before supplying exceptional settlement calls.

## Resolve completed guardian reviews

Keepers can resolve reviews whose window has elapsed:

```bash
sherwood proposal resolve-reviews --vault 0x...
```

Resolution records whether the proposal cleared or reached guardian block quorum.

## Cancel

```bash
sherwood proposal cancel --vault 0x... --id <proposal-id>
```

Without `--emergency`, only the proposer can cancel, and only from `Draft`, `Pending`, `GuardianReview`, or `Approved`. The owner-only `--emergency` path applies only to `Draft` or `Pending`; it is not a bypass for later states. A guardian review cannot be cancelled after its safe cancellation window closes.

## Change per-fund parameters

```bash
sherwood governor --help
sherwood governor set-voting-period --help
sherwood governor set-veto-threshold --help
```

These setters are owner-only, bounded by the contracts, and frozen while any proposal is open. Read the live value again after the transaction.

## Guardian stake operations

```bash
sherwood guardian status [address]
sherwood guardian stake <wood-amount>
sherwood guardian unstake request
sherwood guardian delegate <guardian-address> <wood-amount>
sherwood guardian set-commission <bps>
```

Unstake and undelegation use request, cancel, and claim phases. Query status before assuming a cooldown has completed.
