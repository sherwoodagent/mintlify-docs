---
title: "Configure the CLI"
description: "Set the signer, default vault, RPC endpoint, and local Sherwood state."
---

Sherwood stores local settings in `~/.sherwood/config.json`. The file is created with restricted permissions where the operating system supports them.

## Signing key

For a temporary session, set `PRIVATE_KEY` in the environment:

<Tabs>
  <Tab title="macOS or Linux">
    ```bash
    export PRIVATE_KEY=0x...
    ```
  </Tab>
  <Tab title="PowerShell">
    ```powershell
    $env:PRIVATE_KEY = "0x..."
    ```
  </Tab>
</Tabs>

To persist a dedicated testnet key:

```bash
sherwood config set --private-key 0x...
```

<Warning>
  A key saved with `config set` takes precedence over `PRIVATE_KEY`. Use a dedicated testnet wallet, never paste a production key into shell history, and remove stale saved keys when changing operators.
</Warning>

## Default vault

```bash
sherwood config set --vault 0x...
sherwood vault info
```

The vault is stored under chain ID `46630`. You can override it per command with `--vault`.

## Custom RPC

```bash
sherwood config set --rpc https://your-rpc.example
```

You can also set `ROBINHOOD_TESTNET_RPC_URL`. A saved RPC takes precedence.

## Inspect current settings

```bash
sherwood config show
```

The command should display addresses and endpoints without printing the private key.

## Unsigned calldata mode

Use the global `--calldata-only` flag when an external wallet or agent will sign the transaction:

```bash
sherwood --calldata-only vault deposit \
  --vault 0x... \
  --amount 0.01 \
  --receiver 0x...
```

The CLI prints EIP-5792-style unsigned calls as JSON. Validate the chain, targets, value, and calldata before passing them to a signer.
