The CLI defaults to Robinhood L2 Testnet. You can pass `--chain robinhood-testnet`, but there is no second public fund network to select.

<Note>
  `sherwood fund` is the canonical command group. `sherwood syndicate` remains a backward-compatible alias for existing scripts, but new examples should use `fund`.
</Note>

<Info>
  `sherwood --help` can include development command groups whose external venues are not available on the current deployment. The pages in this documentation cover the deployment-backed fund, vault, governance, guardian, queue, chat, and Portfolio paths.
</Info>

## Read fund state

```bash
sherwood fund list
sherwood fund info <fund-id-or-name>
sherwood vault info --vault 0x...
sherwood vault balance --vault 0x...
```

`fund list` falls back to onchain discovery because the current deployment has no hosted subgraph.

## Create a fund

Fund creation requires:

- a dedicated testnet signer
- testnet ETH for gas
- the required WOOD owner bond prepared in `StakedWood`
- a unique fund label and valid vault asset

<Steps>
  <Step title="Inspect the owner bond">
    ```bash
    sherwood guardian status
    ```
  </Step>
  <Step title="Prepare the bond">
    ```bash
    sherwood guardian prepare-owner-stake <wood-amount>
    ```
  </Step>
  <Step title="Create interactively">
    ```bash
    sherwood fund create
    ```
  </Step>
  <Step title="Verify the result">
    ```bash
    sherwood fund info <fund-id-or-name>
    sherwood config show
    ```
  </Step>
</Steps>

The current testnet does not verify fund agents against a global identity registry. Treat any numeric agent identifier shown by the CLI as deployment-local compatibility metadata, not a portable identity credential.

## Manage deposit access

The owner can approve or remove individual depositors:

```bash
sherwood fund approve-depositor \
  --vault 0x... \
  --depositor 0x...

sherwood fund remove-depositor \
  --vault 0x... \
  --depositor 0x...
```

An open-deposit fund does not require per-address approval. Verify the vault setting before assuming a deposit will succeed.

## Configure the agent fee

```bash
sherwood fund set-agent-fee --vault 0x... --bps 1000
```

`1000` means 10%. The command caps the vault setting at 15%, and the governor can apply a lower performance-fee cap at settlement.

## Deposit and redeem outside a proposal

```bash
sherwood vault deposit --vault 0x... --amount 0.01 --use-eth
sherwood vault redeem --vault 0x... --shares 10
```

`--use-eth` wraps native testnet ETH into the current Synthra WETH9 vault asset. Without it, the wallet must already hold and approve that WETH token.

## Queue liquidity during a proposal

```bash
sherwood queue request-deposit --vault 0x... --amount 0.01 --use-eth
sherwood queue request-redeem --vault 0x... --shares <raw-share-amount>
sherwood queue list --vault 0x...
```

After settlement:

```bash
sherwood queue claim --vault 0x... --id <request-id>
```

A request can be cancelled only before it is stamped to a proposal:

```bash
sherwood queue cancel --vault 0x... --id <request-id>
```

Read [vault liquidity](/protocol/vault-liquidity) before automating queue requests.

## Generate calldata without signing

Place `--calldata-only` before the command group:

```bash
sherwood --calldata-only vault redeem \
  --vault 0x... \
  --shares 10 \
  --receiver 0x... \
  --owner 0x...
```

The output is unsigned. The external signer remains responsible for simulation, chain selection, and final authorization.
