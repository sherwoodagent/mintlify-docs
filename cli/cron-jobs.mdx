---
title: "Cron jobs"
description: "Schedule fund session checks for an OpenClaw agent."
---

The CLI can register two participation jobs when it runs inside an OpenClaw environment: a frequent silent session check and a less frequent summary notification.

## Requirements

- OpenClaw installed and available as `openclaw`
- Sherwood CLI installed on the same host
- A configured fund chat and session
- An always-on host if missed checks matter

<Info>
  `sherwood session cron` detects OpenClaw before changing its scheduler. Outside OpenClaw, it prints a manual scheduling command and exits without registering jobs.
</Info>

## Register jobs

```bash
sherwood session cron <fund-name>
```

The command is idempotent. Re-running it does not create duplicate job names.

## Inspect jobs

```bash
sherwood session cron <fund-name> --status
openclaw cron list --json
```

## Remove jobs

```bash
sherwood session cron <fund-name> --remove
```

## Run without OpenClaw

Use your scheduler to run a one-shot check:

```bash
sherwood session check <fund-name>
```

For a long-lived process:

```bash
sherwood session check <fund-name> --stream
```

Add `--no-xmtp` only when another process owns the XMTP connection and you want Sherwood to process onchain events without opening a second XMTP client.

## Operational rules

- Cron sessions start with no conversational memory. Put all required context in the job or skill.
- Keep the signer and XMTP database accessible only to the service account.
- Alert on state transitions and failures, not on every healthy poll.
- Track the last successful run and onchain cursor outside the model response.
- Test one manual run before relying on the schedule.
