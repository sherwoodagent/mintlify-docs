Strategy templates are ERC-1167 clonable contracts deployed once per chain. Each proposal clones a template, initializes it with custom parameters, then uses the clone in governor batch calls.

<Note>
On Robinhood Chain (chain 4663), the CLI default, `sherwood strategy list` shows **Portfolio**, **Morpho Supply** and **Concentrated Liquidity** from the core protocol, plus two unaudited community templates from `sherwood-strategies` deployed on 4663 since 2026-10-20: **Launchpad** (Sushi venue only) and **Lighter Perp** (CLI 0.99.2 or later). Older templates from earlier deployments (Moonwell Supply, Aerodrome LP, Venice Inference, wstETH Moonwell Yield, Mamo Yield, Hyperliquid Perp, Hyperliquid Grid) appear under "Not available"; none of them can be proposed on 4663. `strategy list` is the source of truth for the active chain.
</Note>

<Info>
While the factory's `ownerOnlyProposals` launch flag is on, only the vault owner can propose. `strategy propose` refuses any other proposer before cloning or locking the bond. See [Governance Commands](/cli/governance-commands).
</Info>

## `strategy list`

Show available strategy templates and their deployed addresses.

```bash
sherwood strategy list
```

## `strategy clone <template>`

Clone a template and initialize it. Returns the clone address for use in proposal batch calls.

```bash
sherwood strategy clone portfolio \
  --vault 0x... \
  --amount 200 \
  --tokens TSLA,AMZN,AMD \
  --weights 4000,3000,3000
```

The clone is deployed and initialized on-chain. The proposer (your wallet) pays gas for both transactions.

## `strategy init <template>`

Initialize a clone that was deployed but not initialized, for example after a clone transaction confirmed and the init did not. It takes the same template flags as `strategy propose`.

```bash
sherwood strategy init portfolio --clone 0xClone --vault 0x... \
  --amount 200 --tokens TSLA,AMZN --weights 6000,4000
```

| Flag | Description |
|------|-------------|
| `--clone <address>` | Clone to initialize. Required |
| `--vault <address>` | Vault address. Required |

## `strategy status <clone>`

Portfolio only. Shows allocations, balances, drift from the target weights, and P&L. `--json` prints machine-readable output.

## `strategy rebalance <clone>`

Portfolio only. Trades each allocation back to its target weight. Weights and routes are frozen at init, so a rebalance can only restore the original basket.

| Flag | Description |
|------|-------------|
| `--max-slippage <bps>` | Tighten the slippage tolerance first. Only a lower value is accepted |
| `--dry-run` | Show what would happen without sending |

## `strategy propose <template>`

<Warning>
**Proposer bond (WOOD).** `propose` pulls a risk-scaled WOOD bond into
`ProposerBondEscrow` — a **second** WOOD spend after the 10,000 WOOD owner stake.
Before signing, the CLI prints the bond quote (`ExposureLedger.proposerBondWood`),
a 5% buffer, your free WOOD and your current allowance. It approves only the
**quote + 5%** (never unlimited), re-quotes right before `propose`, and
re-approves only if the fresh quote exceeds the allowance. It exits with
`InsufficientProposerBondWood` if the wallet balance is short; the wallet must
**hold** the WOOD. The bond is 1% of the proposal's required coverage, converted
to WOOD at half the market price (`0.5 × min(feed, cap)`). `strategy propose`
gives settle calls a cap of 0, so required coverage is about `--amount`, and the
bond is about **2% of `--amount`** in WOOD at market. A WOOD price fall raises
the WOOD count. Do not treat a fixed WOOD number as the requirement; read the
quote. Reclaim the bond after the proposal ends with `sherwood proposal reclaim-bond`
(a settled proposal waits out the 14-day challenge window). See
[Proposer bond](/explanations/proposer-bond).
</Warning>


All-in-one command: clone + initialize + build batch calls + submit proposal (or write JSON files).

- **Thesis attestation is on by default.** A public track-record attestation is made with each proposal unless you pass `--no-attest`. `--attest-thesis <file>` supplies the text; without it the thesis is built from `--name` and `--description`. It never blocks the proposal.
- **Cite the research behind it (CLI 0.100.0 or later).** `--cite <uid>[,<uid>…]` lists `X402_RESEARCH` attestations (yours, to `--vault`; for example a [`news --post`](/cli/commands#news-flash) record) in the thesis and hashes their records into its `dataSnapshotHash`. `--news` runs one FLASH news query for the proposal, posts and attests it to the vault, and cites it: the Portfolio `--tokens` basket (10 items per token, at most 60) or the Lighter Perp `--markets` base assets; any other template prints `nothing to research for a <template> proposal` and proposes without it. `--news` needs a FLASH key and a signing wallet: under `--calldata-only` it refuses (unless there is nothing to research) and prints the `news --post` and `--cite` commands to run instead. A default-built thesis gets a Sources section listing each FLASH headline with its source link and the FLASH credit. Unlike the attestation itself, a citation that fails stops the command before anything is proposed. `--cite` and `--news` cannot be combined with `--data-snapshot`, `--encrypt`, `--no-attest` or `--write-calls`; at most 20 citations. Details: [Cited research](/reference/integrations/eas#cited-research).
- **App link.** After the propose confirms, the CLI prints `Proposal #<id> - view on the vault page: https://app.sherwood.sh/vault/<vault address>`. Share it with the owner. There is no per-proposal page.
- **Guardian coverage.** For Cohort 1 vaults, the Sherwood team guardian covers cohort proposals by default. Execute needs at least one covering guardian approval; see [Tiers and coverage](/explanations/tiers-and-coverage).
- **Tier-2 call cap.** Every core template is tier 2 on 4663, and the whole `--amount` goes on one strategy call. The proposal reverts `Tier2CallCapExceedsCeiling` unless `--amount ≤ totalAssets × tier2CallCapBps / 10,000`. The CLI does not pre-check this; read `sherwood governor info --vault <vault>` first.

<Note>
This command takes no agent-fee flag. The agent fee is the vault's `agentFeeBps`, set by the vault owner via [`sherwood vault set-agent-fee`](/cli/governance-commands#sherwood-vault-set-agent-fee) within the protocol ceiling (for example 20%). Each proposal snapshots it at propose time; the governor clamps that snapshot to `maxPerformanceFeeBps` at settlement.
</Note>

### Keyless (sign-only wallet)

```bash
sherwood --calldata-only strategy propose portfolio \
  --vault 0xVAULT --proposer 0xAGENT \
  --name "TSLA/AMZN basket" --description "60/40 TSLA and AMZN, 7d" \
  --amount 200 \
  --tokens TSLA,AMZN --weights 6000,4000 \
  --swap-routes <TSLA route>,<AMZN route> --max-slippage <largest leg bps> \
  --max-drawdown-bps 2000 \
  --duration 7d
# already pinned a document? replace --name/--description with --metadata-uri ipfs://…

# Morpho Supply, keyless
sherwood --calldata-only strategy propose morpho-supply \
  --vault 0xVAULT --proposer 0xAGENT --name "USDG lending" --description "7d Morpho supply" \
  --market-id <market_id from sources get morpho> --amount 1000 --duration 7d
```

It prints one JSON payload: `WOOD.approve(bondEscrow)` (only when the allowance does not cover the bond), the strategy clone, then `governor.propose`. Broadcast them in order from the `--proposer` wallet; if the clone reverts, do not send the proposal. `--proposer` must be a registered agent on the vault (`vault add`) and, while `ownerOnlyProposals` is on, the vault owner. Set `--max-drawdown-bps` explicitly, tied to the kill criteria you tell the owner. It bounds the fall of the whole vault's price per share, not of `--amount`. The sign-then-broadcast loop is in [External signer](/cli/external-signer).

## Template Options

### portfolio

Weighted basket of tokenized stocks with on-chain rebalancing, swapped through the vault's `UniswapSwapAdapter` over the official Uniswap v3 and v4 deployments on Robinhood Chain. Each basket slot binds a Chainlink push feed, resolved from the address book when `--feeds` is left empty.

| Flag | Description | Default |
|------|------------|---------|
| `--amount <n>` | Total asset amount to allocate (USDG). Becomes the proposal's `maxCapital` | required |
| `--tokens <list>` | Comma-separated token symbols or addresses. The 25 stock tokens with feeds are listed in [Deployments](/reference/deployments#stock-tokens-and-chainlink-feeds) | required |
| `--weights <list>` | Comma-separated weights in bps (must sum to 10000) | required |
| `--max-slippage <bps>` | Max slippage in bps against the Chainlink price, one value for the whole basket; the strategy accepts 50 to 1000 | 500 |
| `--max-slippage-per-leg <list>` | Per-leg slippage bps, same order as `--tokens`. The strategy stores one value, so the CLI resolves it to the largest leg. Not together with `--max-slippage` | none |
| `--swap-routes <list>` | One route per token, same order: `v3:<fee>`, `v4:<fee>:<tickSpacing>` or `v4path:...`; an empty entry auto-detects from the registry's verified pools | auto |
| `--feeds <list>` | Chainlink AggregatorV3 feed per token; an empty slot resolves from the address book | auto |
| `--fee-tier <n>` | Pool fee tier when no route is given | 3000 |
| `--max-drawdown-bps <bps>` | Maximum fall of the **whole vault's** price per share between execute and settle, in bps (0–10000; the governor caps it at 9000). Settle reverts `SettlePriceBelowFloor` below `ppsAtExecute × (1 − bps/10,000)`. Idle vault assets dilute a basket loss, so the basket itself can lose more than this figure. See [Settlement and drawdown](/explanations/settlement-and-drawdown) | 2000 |
| `--swap-adapter <address>` | Override swap adapter | the network's |

**Vault asset.** The strategy's asset must be the vault's own asset, and the protocol's coverage ledger must price one unit of it within 1% of $1 (`AssetNotVaultAsset`, `AssetNotUsdPegged`, `ExposureLedgerUnresolved`). The CLI checks all three before anything is sent; the peg is checked again at execute. Use USDG.

**Weekend feed gap.** Execute, settle and `rebalanceDelta` revert `StalePrice` when a basket token's feed is older than 26 hours. The stock feeds pause over the weekend (52–55 hours between updates), so a proposal holding stock tokens cannot execute, settle or rebalance from about Saturday 18:40 UTC until Monday 00:00 UTC, and an execution window that falls inside the gap expires the proposal. Do not put a stock in a basket across an announced split. Why the 26-hour bound exists: [Oracle staleness](/explanations/oracle-staleness). `sherwood sources get prices` marks each token's `portfolio_price_ok`, and `sherwood sources get calendar` prints the live window; `sherwood sources get liquidity` gives the recommended USDG pool and a suggested `maxSlippageBps` per stock (see [Data feeds](/cli/sources-commands)).

**Routes.** Leave `--swap-routes` out and the CLI auto-detects a route per token by quoting the pools. No route table is fixed for 4663: pools and depth change, so re-quote before every proposal with `sherwood sources get liquidity` and pass the routes it picks.

#### From a liquidity record to Portfolio flags

`sherwood sources get liquidity` returns `recommended.by_symbol[SYM]` for each stock: the best hookless, USDG-quoted Uniswap pool at a $10k size, with

| Record field | Example | Flag |
|---|---|---|
| `swap_extra_data_hint` `{mode: 0, fee}` (Uniswap v3) | `{mode: 0, fee: 3000}` | that leg of `--swap-routes`: `v3:3000` |
| `swap_extra_data_hint` `{mode: 2, fee, tickSpacing}` (Uniswap v4) | `{mode: 2, fee: 3000, tickSpacing: 60}` | that leg of `--swap-routes`: `v4:3000:60` |
| `fee` | `3000` | `--fee-tier 3000` only when every leg is v3 at the same fee; `--swap-routes` overrides it per leg |
| `suggested_max_slippage_bps` | `150` | `--max-slippage`: the **largest** value across the legs |

`--max-slippage` is one value for the whole basket, so use the largest leg's `suggested_max_slippage_bps`. Or pass `--max-slippage-per-leg <a,b,c>` (same order as `--tokens`, not together with `--max-slippage`): the strategy stores one value, so the CLI resolves it to the largest leg. A record with `swap_extra_data_hint: null` is not routable by the swap adapter: drop that token.

```bash
T=TSLA,AMZN,AMD
L=$(sherwood sources get liquidity)
ROUTES=$(echo "$L" | jq -r --arg t "$T" '[$t|split(",")[] as $s | .recommended.by_symbol[$s].swap_extra_data_hint
  | if .mode == 0 then "v3:\(.fee)" else "v4:\(.fee):\(.tickSpacing)" end] | join(",")')
SLIP=$(echo "$L" | jq --arg t "$T" '[$t|split(",")[] as $s | .recommended.by_symbol[$s].suggested_max_slippage_bps] | max')
sherwood --calldata-only strategy propose portfolio --vault 0xVAULT --proposer 0xAGENT \
  --name "TSLA/AMZN/AMD basket" --description "40/30/30, 7d" \
  --amount 200 --tokens $T --weights 4000,3000,3000 \
  --swap-routes "$ROUTES" --max-slippage "$SLIP" --max-drawdown-bps 2000 --duration 7d
```

See the [Portfolio strategy reference](/protocol/strategies/uniswap) for mechanics and risk notes.

### morpho-supply

Supply the vault asset to one Morpho Blue market. Settlement withdraws the whole position, interest included. The market must be allowlisted by id on the `TierRegistry` (`MorphoMarketNotAllowed` otherwise) and its loan token must be the vault asset; the preflight checks both before anything is sent. Allowlisting is a protocol-owner action, so a refused market is not retried.

```bash
sherwood strategy propose morpho-supply \
  --vault 0x... \
  --market-id 0x0309c02dabf0be02682af1a2bde9a457f4df0f0b6bc889cde3f948e5315e4114 \
  --amount 1000 \
  --name "USDG lending" --duration 7d
```

| Flag | Description | Default |
|------|------------|---------|
| `--market-id <bytes32\|recommended>` | Morpho Blue market to supply. `recommended` takes the [sources](/cli/sources-commands) pick for `--amount` (needs `sherwood sources login`) | required |
| `--amount <n>` | Vault asset to supply | required |
| `--morpho <address>` | Morpho Blue singleton | the network's `MORPHO_BLUE` |

Let the data feed pick the market:

```bash
sherwood sources login
sherwood strategy propose morpho-supply --vault 0x... --market-id recommended --amount 10000 \
  --name "USDG lending" --duration 7d
```

The CLI prints the pick and its reasons, then runs the same on-chain preflight as with an explicit id.

See [Morpho Supply](/protocol/strategies/morpho-supply).

### concentrated-liquidity

A Uniswap V3 range position funded by a Morpho borrow against vault-asset collateral. The TierRegistry must allowlist the strategy's counterparties (swap adapter, position manager, Morpho, the Uniswap factory and the pool's other token) and the Morpho market by id; the preflight names any that are missing (`CounterpartyNotAllowed`, `MorphoMarketNotAllowed`).

```bash
sherwood strategy propose concentrated-liquidity \
  --vault 0x... \
  --pair-token WETH --pool-fee 100 \
  --market-id 0x0309c02dabf0be02682af1a2bde9a457f4df0f0b6bc889cde3f948e5315e4114 \
  --collateral-amount 1000 --borrow-amount 800 \
  --range-pct 5 \
  --name "USDG/WETH range" --duration 7d
```

|------|------------|---------|
| `--market-id <bytes32>` | Morpho Blue borrow market | required |
| `--collateral-amount <n>` | Vault asset pulled at execute and posted as Morpho collateral | required |
| `--borrow-amount <n>` | Vault asset borrowed against it and deployed into the range | required |
| `--pool <address>` | Uniswap V3 pool | or `--pair-token` + `--pool-fee` |

| `--pool-fee <fee>` | Pool fee tier in hundredths of a bip, e.g. 100 / 500 / 3000 | with `--pair-token` |
| `--range-pct <pct>` | Range of ±pct around the spot tick, snapped outward to tick spacing | or `--tick-lower` + `--tick-upper` |

| `--expected-liquidity <n>` | Override the computed expected V3 liquidity | V3 liquidity math at spot |

### launchpad

Launch a fund token on Sushi Launchpad V2 or StonkBrokers with vault capital. Holders claim a pro-rata slice of a reserve.

<Warning>
**Unaudited community template.** The Launchpad template and its launch adapters come from [sherwood-strategies](https://github.com/sherwoodagent/sherwood-strategies) and are unaudited. The template and the Sushi launch adapter have been deployed on Robinhood Chain (4663) since 2026-10-20; the template was redeployed on 2026-10-22 at `0x1F8221c4176B8B017A6Ef699947BB4A33730Df32` with the `DeadlineInPast` fix. StonkBrokers is not deployed there, so only `--venue sushi` works on 4663; `--venue stonk` is refused. Class certification is pending, so a launch prices as an uncertified tier-2 call at full notional. See [Mainnet rules on 4663](#mainnet-rules-on-4663).
</Warning>

<Warning>
A launch settles as a vault-asset **loss** of about `--asset-in`, by design on v1: the reserve is a dividend in kind to holders, and v1 books no value for the launch token. The CLI sets `--max-drawdown-bps` to `ceil(assetIn / totalAssets) + 200` bps when you omit it, refuses a lower value, and refuses the proposal if the result is above 9,000 bps. See [Launchpad](/protocol/strategies/launchpad#drawdown).
</Warning>

sherwood strategy propose launchpad \

  --venue sushi --quote USDG \
  --asset-in 1000 --reserve 160000000 \
  --claim-window 7d \
  --token-name "Robin Fund" --token-symbol ROBIN \
  --name "Launch ROBIN" --duration 8d

#### Mainnet rules on 4663

CLI 0.99.0 and later enforce these rules on Robinhood Chain (4663) before anything is sent:

- **Sushi only.** No StonkBrokers launch adapter is deployed on 4663, so `--venue stonk` is refused there. StonkBrokers runs on the fork only.
- **The quote defaults to the vault asset.** A USDG vault launching against USDG runs no asset→quote swap, so there is no swap leg to sandwich at execute. Any other quote the venue supports is allowed under the rules below.
- **`--min-tokens-out` equals `--reserve`.** On Sushi, omit `--min-tokens-out` and it defaults to `--reserve`. A lower value is refused (F-7, execute would revert `ReserveFloorBelowReserve`). A higher value is refused too (F-5): tokens the dev buy delivers above the reserve are never claimable and reach the vault in kind at settle, where nothing can dispose of them. This applies to Sushi on every chain.
- **Size `--reserve` from a measured launch.** Sushi Launchpad V2 has no dev-buy quoter, so the CLI cannot quote the dev buy. Set `--reserve` close to what the dev buy returns. At writing, the measured reference is about 164.56M tokens per 1,000 USDG. Sushi mints a fixed 1B supply, and the reserve is capped at 20% of it.

A USDG vault launching with 1,000 USDG:

```bash
sherwood strategy propose launchpad \
  --vault 0x... \
  --venue sushi --quote USDG \
  --asset-in 1000 --reserve 160000000 \
  --claim-window 7d \
  --token-name "Robin Fund" --token-symbol ROBIN \
  --name "Launch ROBIN" --duration 8d
```

`--min-tokens-out` is left out, so it equals the 160M reserve. The gap to the 164.56M reference is the slippage room. The dev buy reverts if it would return less than the reserve.

#### Quoting in another token

A launch quoted in a token other than the vault asset (for example TSLA on a USDG vault) swaps the asset into the quote at execute. Execution is permissionless, so the swap's floor is what a sandwich can take. The CLI adds these rules on every chain. Each one refuses the proposal.

- **Floor.** `minQuoteOut` is the swap adapter's quote for the swap amount, less `--max-slippage-bps` (default 50, at most 100). A lower `--min-quote-out` is refused.
- **Thin pool.** The price impact at `--asset-in` may not exceed `--max-slippage-bps`. The refusal estimates what the pool can take.
- **Pool vs feed (Sushi).** The quote at size may sit at most 300 bps under the output the venue's own asset and quote feeds imply.
- **Size cap.** `--asset-in` is at most 3,500 bps of `totalAssets`, the class bound.
- **Fresh feed.** The venue's quote feed must have updated within 3 days, or the venue reverts `StalePriceFeedRound`. Stock feeds do not update on weekends or market holidays.

The deadline is the same as for an asset-quoted launch: `--deadline`, otherwise the governor windows plus one day, and `0` for none. A past `--deadline` is refused (`DeadlineInPast`). The launch is executable as voted. CLI 0.99.3 dropped the earlier disarmed design, which proposed these launches with `deadline = 1` and required `sherwood launchpad arm` before execute.

Arming is optional. Right before execute, the proposer may run `sherwood launchpad arm` (below) to raise the floor to a fresh swap-adapter quote and set a short deadline.

```bash
sherwood strategy propose launchpad \
  --vault 0x... \
  --venue sushi --quote TSLA \
  --asset-in 1000 --reserve 155000000 \
  --claim-window 7d \
  --token-name "Robin Fund" --token-symbol ROBIN \
  --name "Launch ROBIN" --duration 8d

# optional, right before execute: fresh floor, short deadline
sherwood launchpad arm 0xStrategy
sherwood proposal execute --vault 0x... --id <id>
```

Creator fees on such a launch arrive at the vault in the quote token and the launch token. Nothing converts them to the asset, and v1 `totalAssets` books no value for them.

See [Launchpad](/protocol/strategies/launchpad).

## `launchpad` commands

Operator commands for a Launchpad clone. Every write runs its own preflight and honours the global `--calldata-only` flag.

| Command | What it does |
|---------|--------------|
| `sherwood launchpad status <strategy> [--holder <address>] [--json]` | Launch, reserve, claim window, venue. `--holder` shows that holder's claim. |
| `sherwood launchpad arm <strategy> [--swap-deadline <duration>] [--max-slippage-bps <bps>] [--quote-swap-route <spec>] [--proposer <address>]` | Optional. Proposer only, before execute, for a launch quoted in a non-asset token. Re-quotes the swap and re-runs the feed, thin-pool and feed-skew checks, then calls `updateParams` with `minQuoteOut` raised to the fresh floor (never lowered) and a venue deadline `--swap-deadline` from now (default 10m, at most 1h). `--max-slippage-bps` defaults to 50 (1-100). Pass `--quote-swap-route` if the proposal used a route other than the default. `--proposer` names the signer for the preflight with `--calldata-only`. |
| `sherwood launchpad claim <strategy>` | Claim your pro-rata slice of the reserve (dividend in kind; shares are not burned). With `--calldata-only`, `--holder` names the external signer for the preflight. |
| `sherwood launchpad claim-for <strategy> <holder>` | Pay a holder their slice (permissionless; tokens go to the holder, never the caller) |
| `sherwood launchpad collect-fees <strategy>` | Push the launch's accrued creator fees to the vault (permissionless; never pays the caller). Sherwood's keeper does this automatically — this is the manual fallback |
| `sherwood launchpad collect-fees <strategy> --dry-run [--json]` | Simulate the collection and print the quote/token fees it would move. Sends nothing |
| `sherwood launchpad finalize <strategy>` | Graduate and bond a StonkBrokers launch (no-op on Sushi, which is live from the launch block) |

Collect fees often when the launch is quoted in the vault asset: a large pending lump can be sniped by a deposit just before collection. See [Fees](/protocol/strategies/launchpad#fees).

`arm` refuses when the pool now quotes under the voted floor (execute would revert `QuoteAcquisitionFailed`), when the signer is not the proposer, when the clone has executed, or when the launch is quoted in the vault asset. If you arm, submit the execute right after: the CLI has no private submission on Robinhood Chain, so the window is public. Arming is not required: a launch is executable as voted, and one not executed by `executeBy` expires with the vault untouched.

## `lighter` commands

Operator commands for a Lighter Perp clone. They are ready for when the template deploys.

| Command | What it does |
|---------|--------------|
| `sherwood lighter keygen [--key-index <n>] [--force] [--print-private-key] [--json]` | Generate the agent's Lighter L2 API key and save it to `~/.sherwood/config.json` (0600). Needs Lighter's Python SDK: `pip install lighter-sdk` (`LIGHTER_PYTHON` selects the interpreter). |
| `sherwood lighter markets [--json]` | List Lighter perp markets (ids are what `--markets` takes) |
| `sherwood lighter status <strategy> [--json]` | On-chain lifecycle plus off-chain positions and margin |
| `sherwood lighter register-key <strategy>` | `registerAgentKey()`: register the stored agent key (after execute) |
| `sherwood lighter guardrail cancel-all <strategy>` | Cancel every resting order |
| `sherwood lighter guardrail close-market <strategy> <market> [--side long\|short] [--price <n>]` | Market-close one position, on any market. `--price` is a protective bound in venue ticks. |
| `sherwood lighter guardrail rotate-key <strategy> [--pubkey <hex>] [--burn]` | Replace the agent key, or retire it to a burn key |
| `sherwood lighter initiate-return <strategy> [--force]` | Exit step 1: cancel all and close every configured market. Queues nothing. |
| `sherwood lighter queue-withdraw <strategy> --all` | Exit step 2: queue the true L2 balance, read from the Lighter API. Refuses with any open position. `--ticks <n>` queues an explicit amount. |
| `sherwood lighter prepare-settle <strategy> [--pubkey <hex>] [--assume-drained] [--dry-run]` | Verify nothing is at the venue or in flight, then rotate the agent key to a burn key. Required before settle. |
| `sherwood lighter acknowledge-shortfall <strategy> --yes` | Waive the settle guard's "everything queued came back" check after a real venue under-fill |
| `sherwood lighter recover <strategy>` | `recoverResiduals()`: claim matured USDG onto the clone (permissionless). Does not push to the vault. |

<Warning>
Rotate the agent key before settle (`prepare-settle`): after settlement nobody can rotate it. Never put `rescueTo(USDG)` before `settle()` in one batch: settle then reverts and only the owner's emergency path gets out. Residual margin left after settle must be recovered promptly, because deposits reopen while it is still out.
</Warning>

## How It Works

1. **Clone**: The CLI deploys an ERC-1167 minimal proxy pointing to the template singleton. Cost: ~50k gas.
2. **Initialize**: Calls `strategy.initialize(vault, proposer, data)` with your parameters. Cost: ~100-200k gas.
3. **Build calls**: Generates `execute.json` and `settle.json` with the correct approve + execute/settle batch calls.
4. **Submit**: Either writes files for `proposal create` or calls `governor.propose()` directly.

Before any transaction, the Launchpad, Lighter Perp, Morpho Supply and Concentrated Liquidity templates check their `_initialize` conditions on-chain and report every failure in one message, with the contract's error name and selector.

The vault trusts the governor — no separate allowlisting step is needed for strategy clones, which the clone flow registers on the `StrategyFactory`. The venues a strategy calls (adapters, lending markets, collateral and pool tokens) are a separate, strategy-side check against `TierRegistry.isCounterpartyAllowed` and `isMorphoMarketAllowed`, set by the registry owner. Uncertified calls are not refused; they are priced at tier 2 (full notional), which sets the guardian coverage the proposal needs and the proposer bond it pulls.

`sherwood proposal show <id> --vault <vault>` prints where a proposal's strategy came from (a core-protocol template, a `sherwood-strategies` template, an unknown template, or hand-written code registered directly on the factory); see [Governance Commands](/cli/governance-commands).
