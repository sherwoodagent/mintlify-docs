---
title: "Portfolio walkthrough"
description: "Prepare, inspect, submit, and settle a Portfolio proposal."
---

This walkthrough shows the operator sequence. It intentionally uses placeholders for routes and feeds because the current CLI registry does not provide verified stock defaults.

<Warning>
  Every command targets testnet, but it can still send transactions and spend testnet assets. Verify addresses and simulate calls before submission.
</Warning>

<Steps>
  <Step title="Check the deployed template">
    ```bash
    sherwood strategy list
    ```

    Continue only if `portfolio` is listed with the template address from [deployments](/reference/deployments).
  </Step>

  <Step title="Set the proposal inputs">
    Use contract addresses, not unverified ticker text, for any token without a verified CLI route.

    ```bash
    export VAULT=0x...
    export TOKEN_A=0x...
    export TOKEN_B=0x...
    export FEED_A=0x...
    export FEED_B=0x...
    ```

    The example weights below allocate 60% to token A and 40% to token B.
  </Step>

  <Step title="Build the calls for review">
    ```bash
    sherwood strategy propose portfolio \
      --vault "$VAULT" \
      --name "Two-asset test basket" \
      --description "Testnet basket with explicit routes, feeds, and exit assumptions" \
      --duration 24h \
      --amount 0.01 \
      --tokens "$TOKEN_A,$TOKEN_B" \
      --weights "6000,4000" \
      --swap-routes "v3:3000,v3:3000" \
      --feed-ids "$FEED_A,$FEED_B" \
      --price-decimals "8,8" \
      --max-slippage 300 \
      --write-calls ./portfolio-calls
    ```

    `--write-calls` writes the execute and settlement arrays instead of submitting the governance proposal. In signer mode, the command may still deploy and initialize the strategy clone. Read the confirmation prompts and transaction summary.
  </Step>

  <Step title="Inspect both call arrays">
    Confirm the following before using them:

    - the vault and clone addresses
    - the exact approved asset amount
    - the adapter and route bytes for every basket token
    - the settlement path back to the vault asset
    - the proposal duration and metadata
  </Step>

  <Step title="Submit the proposal">
    Run the same `strategy propose portfolio` command without `--write-calls` after review. Record the vault-scoped proposal ID from the output.
  </Step>

  <Step title="Vote and execute">
    ```bash
    sherwood proposal vote --vault "$VAULT" --id <proposal-id> --support for
    sherwood proposal execute --vault "$VAULT" --id <proposal-id> --dry-run
    sherwood proposal execute --vault "$VAULT" --id <proposal-id>
    ```
  </Step>

  <Step title="Monitor the clone">
    ```bash
    sherwood strategy status <clone-address>
    sherwood strategy status <clone-address> --json
    ```
  </Step>

  <Step title="Settle after the strategy window">
    ```bash
    sherwood proposal settle --vault "$VAULT" --id <proposal-id>
    ```

    Settlement returns assets to the vault and stamps the price used by queued claims.
  </Step>
</Steps>

## Failure checks

| Failure | What to verify |
| --- | --- |
| Template unavailable | Chain ID and template allowlist |
| Quote unavailable | Pool liquidity, adapter, and encoded route |
| Stale or invalid price | Feed address, feed decimals, and allowed age |
| Weight error | Every list has the same length and weights total `10000` |
| Execution reverts | Asset approval, clone state, proposal state, and slippage |
| Settlement reverts | Exit liquidity and settlement call array |
