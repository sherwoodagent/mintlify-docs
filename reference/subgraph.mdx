**No subgraph indexes Sherwood on Robinhood Chain (4663).** The subgraph manifests in the protocol repo target an older deployment, and their single-governor data source does not fit v1, where every vault has its own governor. Do not set `SUBGRAPH_URL`.

Read the chain directly instead. Every path below returns live state.

## Pick a read path

| You have | Use |
|---|---|
| A TypeScript runtime | The [SDK](/api/sdk) read helpers |
| Only HTTP | The [HTTP API](/api/overview#read-endpoints-get) read routes |
| A shell | The `sherwood` CLI read commands |
| Any RPC client | Direct contract calls on the factory and the vault's governor |

## SDK

Each helper takes a viem `PublicClient` pointed at a 4663 RPC.

| Read | Returns |
|---|---|
| `readActiveFunds(client, chainId, { limit? })` | Active funds from the factory, newest first |
| `readFundResolution(client, chainId, { vault?, subdomain? })` | One fund, resolved by vault address or subdomain |
| `readVaultInfo(client, vault)` | Vault state: total assets, share supply, owner, governor, asset metadata |
| `resolveGovernor(client, chainId, vault)` | The vault's governor address |
| `readGovernorParams(client, chainId, vault)` | That governor's parameters plus the protocol fee splits |
| `readProposal(client, chainId, vault, proposalId)` | One proposal in full |

```ts
import { readActiveFunds, readProposal, CHAIN_IDS } from "@sherwoodagent/sdk";

const funds = await readActiveFunds(client, CHAIN_IDS.ROBINHOOD, { limit: 25 });
const p = await readProposal(client, CHAIN_IDS.ROBINHOOD, funds[0].vault, 1n);
```

## HTTP API

Base URL `https://api.sherwood.sh`. Pass `chain=4663`.

| Route | Returns |
|---|---|
| `GET /funds?chain=4663&limit=25` | Active funds, newest first |
| `GET /funds/resolve?chain=4663&subdomain=<name>` | One fund by `vault` or `subdomain` |
| `GET /vaults/:address?chain=4663` | Vault state |
| `GET /governor?chain=4663&vault=0x…` | That vault's governor parameters and fee splits |
| `GET /proposals?chain=4663&vault=0x…&state=Pending` | Recent proposals, with optional filters |
| `GET /proposals/:id?chain=4663&vault=0x…` | One proposal |

See [HTTP API](/api/overview) for parameters and response shapes.

## CLI

```bash
sherwood vault list                         # active funds
sherwood vault info <subdomain>             # one fund: assets, rules, lock state
sherwood proposal list --vault <vault>      # a vault's proposals
sherwood proposal show <id> --vault <vault> # one proposal, with guardian coverage
sherwood governor info --vault <vault>      # governor parameters and caps
```

## Direct RPC

The factory is `0x619af1488F32B4797f6faDa3C3a8De72a5B693E0` ([Deployments](/reference/deployments)). There is no singleton governor; resolve each vault's governor from the factory.

```bash
RPC=https://rpc.mainnet.chain.robinhood.com
F=0x619af1488F32B4797f6faDa3C3a8De72a5B693E0

cast call $F 'syndicateCount()(uint256)' --rpc-url $RPC
cast call $F 'getAllActiveSyndicates()' --rpc-url $RPC
cast call $F 'governorOf(address)(address)' <vault> --rpc-url $RPC

G=$(cast call $F 'governorOf(address)(address)' <vault> --rpc-url $RPC)
cast call $G 'proposalCount()(uint256)' --rpc-url $RPC
cast call $G 'getProposal(uint256)' 1 --rpc-url $RPC
```

`getActiveSyndicates(offset, limit)` pages the same list. Proposal ids are per vault and start at `1`. For history (deposits, withdrawals, votes), read the contracts' event logs with `eth_getLogs` on the vault and its governor.
