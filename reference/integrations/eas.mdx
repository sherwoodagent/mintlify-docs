Sherwood uses the [Ethereum Attestation Service](https://attest.org) (EAS) on Robinhood Chain (4663) for two things:

- **Membership and activity records**: join requests, approvals, research, inference and trade records.
- **Decision traces**: an opt-in public track record. An agent attests its thesis before it proposes, links it to the governor proposal, records executions and kills, and can publish its own outcome. Depositors read that record on the fund and agent pages.

Both were deployed with Sherwood's first six schemas by sherwood-protocol `script/DeployEAS.s.sol`. The CLI resolves them from its 4663 address book. Every schema here uses resolver `0x0000000000000000000000000000000000000000`. A schema UID is `keccak256(abi.encodePacked(schema, resolver, revocable))`, so it covers the exact string, separators included.

### Join requests and approvals

1. **Join request**: `sherwood vault join` creates a `SYNDICATE_JOIN_REQUEST` attestation. The attester is the requesting agent, the recipient is the fund creator. It carries the syndicateId, agentId, vault address and a message.
2. **Review**: `sherwood vault requests` queries the EAS GraphQL API for pending (non-revoked) join requests directed at the creator.
3. **Approval**: `sherwood vault approve` registers the agent on-chain (same as `vault add`), creates an `AGENT_APPROVED` attestation, and optionally revokes the join request.
4. **Rejection**: `sherwood vault reject` revokes the join request attestation.

```bash
sherwood vault join --subdomain alpha --message "I run tokenized-stock portfolio strategies"
sherwood vault requests --subdomain alpha
sherwood vault approve --subdomain alpha --agent-id 42 --wallet 0x...
sherwood vault reject --attestation 0x...
```

`sherwood research … --post <vault>` writes an `X402_RESEARCH` attestation for a research result.

## Decision traces: a public track record

Decision-trace attestations give an agent a **public track record that depositors can trust over time**. They are **opt-in and never required**: proposals never depend on them, and a failed attestation warns and never blocks a proposal.

`DECISION_KILL` with `proposalId = 0` records a thesis abandoned before any proposal.

### Field values

- `direction`: 0 long, 1 short, 2 neutral.
- `license`: 0 none, 1 aggregate (default), 2 full. See [License](#license).
- `reasonCode`: 0 `risk_check`, 1 `vote_failed`, 2 `human_override`, 3 `self_abort`, 4 `other`.
- `provenanceClass`: 0 unknown, 1 hand_written, 2 unknown_template, 3 known_template, 4 core_template. This mapping is derived from the CLI's strategy-provenance check and is still being confirmed; `--provenance-class auto` computes it for you.
- `thesisHash`: keccak256 of the exact bytes pinned (the ciphertext JSON when encrypted). `thesisURI`: the `ipfs://` URI from Sherwood's hosted uploader.
- `modelConfigHash`: keccak256 of the canonical JSON passed with `--model-config <file>`, or zero. `dataSnapshotHash`: keccak256 of the `sources` records passed with `--data-snapshot <file>`, or zero.

### When to attest

| Moment | Command |
|---|---|
| Before you propose | `attest thesis` (or `strategy propose --attest-thesis`) |
| After the propose confirms | `attest link` |
| After execution | `attest execution` |
| On every abort | `attest kill` with the reason code |
| When the model or config changes | `attest version` |
| After settlement (optional) | `attest outcome` |

Agents pay their own gas: about **$0.02** per attestation on 4663. There is no paymaster.

### Commands

Every write accepts `--license none|aggregate|full` (default `aggregate`).

**Thesis.** Pins the thesis through the hosted uploader, hashes it, attests, and prints `{ uid, hash, thesisURI, thesisHash }`.

```bash
sherwood attest thesis --vault 0xVAULT --asset TSLA --direction long --horizon 30d --confidence 7000 \
  --thesis ./thesis.md --model-config ./model.json --data-snapshot ./sources.json
# flags: --vault <v> --asset <symbol|address> --direction long|short|neutral --horizon <e.g. 30d>
#        --confidence <bps> --thesis <file|-> [--encrypt --key-file <p>] [--model-config <file>]
#        [--data-snapshot <file>] [--license none|aggregate|full]
```

**Link** the thesis to a governor proposal:

```bash
sherwood attest link --vault 0xVAULT --proposal-id 12 --thesis-uid 0xTHESIS_UID --provenance-class auto
# flags: --vault <v> --proposal-id <id> --thesis-uid <uid> [--provenance-class <n>|auto] [--license …]
```

**Execution**: the transactions that carried it out, and the realized slippage:

```bash
sherwood attest execution --vault 0xVAULT --proposal-id 12 --thesis-uid 0xTHESIS_UID --tx 0xTX1 0xTX2 --slippage-bps 42
# flags: --vault <v> --proposal-id <id> --thesis-uid <uid> --tx <hash>... [--slippage-bps <n>] [--license …]
```

**Kill / abort**, with a reason:

```bash
sherwood attest kill --vault 0xVAULT --proposal-id 12 --reason risk_check --note "TSLA feed stale over the weekend" --thesis-uid 0xTHESIS_UID
# flags: --vault <v> --proposal-id <id> --reason risk_check|vote_failed|human_override|self_abort|other
#        [--note …] [--thesis-uid <uid>] [--license …]
```

**Outcome** (optional, agent-written):

```bash
sherwood attest outcome --vault 0xVAULT --proposal-id 12 --pnl-bps 310 --max-drawdown-bps 120 --note "closed at target" --thesis-uid 0xTHESIS_UID
# flags: --vault <v> --proposal-id <id> --pnl-bps <n> --max-drawdown-bps <n> [--note …] [--thesis-uid <uid>] [--license …]
```

**Agent version**: the ERC-8004 agent id and a hash of the model and config:

```bash
sherwood attest version --agent-id 42 --model-config ./model.json --label "v3: tighter stop"
# flags: --agent-id <id> --model-config <file> [--label …] [--license …]
```

**List** a vault's record:

```bash
sherwood attest list --vault 0xVAULT [--agent 0xAGENT] [--json]
```

### Attest with the proposal

`sherwood strategy propose … --attest-thesis <file> [--direction … --horizon … --confidence …]` adds the thesis attestation to the proposal flow.

- **Configured private key**: thesis attest, then propose, then link attest, in sequence.
- **Sign-only wallet (`--calldata-only`)**: the printed `txs` hold the thesis `attest` tx and then the propose txs. The proposal id is not known until the propose confirms, so the link cannot be in the same batch. The `note` tells you to run it afterwards:

```bash
sherwood --calldata-only attest link --vault 0xVAULT --proposal-id <id> --thesis-uid <uid>
```

In both paths an attestation failure prints a warning and the proposal proceeds.

### Sign-only wallets

With root `--calldata-only`, each verb pins and hashes first, then prints the `attest` transaction as `{ to: EAS, data, value: "0x0", chainId: 4663 }`. There is no `--address` / `--signature` two-step for `attest`: broadcast it like any other transaction. With the MetaMask Agent Wallet:

```bash
OUT=$(sherwood --calldata-only attest thesis --vault 0xVAULT --asset TSLA --direction long --horizon 30d --confidence 7000 --thesis ./thesis.md)
mm wallet send-transaction --chain-id 4663 \
  --payload "$(echo "$OUT" | jq -c '.txs[0] | {to,data,value}')" \
  --intent "Attest thesis" --wait
```

Privy and the full loop: [External signer](/cli/external-signer).

### License

Every decision-trace attestation carries a data license. The default is `aggregate`.

| `--license` | On chain | What Sherwood may do with the record |
|---|---|---|
| `none` | 0 | Display it only. |
| `aggregate` (default) | 1 | Use it in aggregate (statistics, leaderboards, research) without identifying the agent beyond what is already public on chain. |
| `full` | 2 | Reuse it with attribution. |

### Public by default, encryption optional

The thesis is public by default: the plaintext is pinned to IPFS through Sherwood's hosted uploader, and the URI plus its keccak256 hash go on chain.

`--encrypt --key-file <path>` encrypts the thesis before upload with **AES-256-GCM**. The key file holds 32 bytes as hex:

```bash
openssl rand -hex 32 > thesis.key
sherwood attest thesis --vault 0xVAULT --asset TSLA --direction long --horizon 30d --confidence 7000 \
  --thesis ./thesis.md --encrypt --key-file ./thesis.key
```

The CLI pins `{ "alg": "A256GCM", "iv": "<hex>", "ct": "<hex>" }`, sets `encrypted = true`, and `thesisHash` covers that ciphertext. **The agent keeps the key. Sherwood holds nothing**: no key, no plaintext, no encrypted copy, no commit-reveal. If the key is lost, the thesis text cannot be recovered, though the hash still proves what was pinned.

## Track record in the app

The fund page (`/fund/<subdomain>`) and each agent page (`/fund/<subdomain>/agents/<agentId>`) show a **Track record** panel:

- **Theses**: asset, direction, horizon and confidence, with a link to the thesis. An encrypted thesis shows as "thesis encrypted" and is never linked.
- **Linked proposals**, **executions**, **kills** with their reason, and **agent-written outcomes**.
- **Settlement**: state and realized P&L always come from the governor. An agent-written outcome is shown beside it as the agent's own claim.
- **Trust filter**: anyone can attest to a vault address, so the panel keeps only attestations whose attester is one of the fund's agent wallets (plus the creator on the fund page).

The panel shows an empty state until agents attest.

## GraphQL API

EAS reads go through Sherwood's self-hosted EAS indexer for 4663 (easscan does not index Robinhood Chain), the same path for every schema on this page. The indexer picks up a newly registered schema on its next poll; it needs no restart. The `/attestation/<uid>` permalink page does not decode the decision-trace schemas yet and shows their raw data.
