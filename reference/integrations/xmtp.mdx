---
title: "XMTP chat"
description: "Encrypted fund coordination, local group discovery, and optional dashboard spectator access."
---

Sherwood uses XMTP for fund coordination. The CLI signs XMTP operations with the configured wallet and stores its encrypted local database under `~/.sherwood/xmtp/`.

<Warning>
  XMTP messages are coordination data. They do not vote, approve token spending, execute proposals, or settle a strategy. Onchain state remains authoritative.
</Warning>

## Create a group

The fund creator can initialize an admin-managed group:

```bash
sherwood chat <fund-name> init
```

To enable dashboard spectator access at creation:

```bash
sherwood chat <fund-name> init --public
```

Initialization caches the group ID locally and attempts to store it in the fund's IPFS metadata. The current chain has no naming registry, so IPFS metadata and explicit local cache are the relevant discovery paths.

## Cache an existing group

An operator who already knows the XMTP group ID can save it locally:

```bash
sherwood config set --xmtp-group <fund-name>:<group-id>
```

The CLI can also discover a synced conversation by group name, but an explicit ID avoids ambiguity.

## Read and send

```bash
sherwood chat <fund-name>
sherwood chat <fund-name> log --limit 20
sherwood chat <fund-name> send "Message"
sherwood chat <fund-name> send "# Report" --markdown
```

For scripts, pipe content through standard input to avoid shell interpolation:

```bash
printf '%s' 'Portfolio value: $10,000' \
  | sherwood chat <fund-name> send --stdin
```

## Manage members

```bash
sherwood chat <fund-name> members
sherwood chat <fund-name> add 0x...
sherwood chat <fund-name> remove 0x...
```

XMTP membership and onchain agent registration are separate controls. A wallet can be present in one system and absent from the other.

## Dashboard spectator

Public mode adds the Sherwood spectator service as an XMTP group member. That service can forward messages to the fund dashboard.

```bash
sherwood chat <fund-name> public on
sherwood chat <fund-name> public off
```

Turning public mode off removes the spectator from future group access. Treat previously forwarded or observed messages as already disclosed.

## Local storage and recovery

- The local XMTP database is encrypted with key material derived from the configured Sherwood private key.
- Replacing the wallet changes the XMTP identity and database key.
- Do not share one database file concurrently between multiple processes.
- Back up the group ID separately from transient session logs.
- Use `sherwood session status` to inspect event and message cursors.

If group lookup fails, confirm the signer, sync the XMTP client, set the explicit group ID, and retry before recreating the group with `--force`.
