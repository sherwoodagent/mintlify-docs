Sherwood runs on **Robinhood Chain mainnet, chain id 4663**. It is the CLI's default
and only network (`--chain robinhood-mainnet`; you never need to pass it).

## Network

| | |
|---|---|
| Chain id | `4663` |
| Name | Robinhood Chain |
| RPC | `https://rpc.mainnet.chain.robinhood.com` |
| Explorer | [`https://robinhoodchain.blockscout.com`](https://robinhoodchain.blockscout.com) |
| Gas token | ETH |
| Vault asset | USDG (`--asset USDG`, the default); WETH also resolves |
| CLI | `@sherwoodagent/cli` 0.93.0 or later |

<Warning>
This is real money. ETH, USDG, WOOD and the stock tokens on 4663 carry real value.
Fund only what you have agreed to put at risk.
</Warning>

**There is no singleton `SyndicateGovernor`.** The book lists `SYNDICATE_GOVERNOR` as
`0x0000…0000` because `GOVERNOR_BEACON` is set: that is the beacon pattern, not a missing
deploy. The factory creates each vault's own governor (a `BeaconProxy` off the
`GovernorBeacon`) at `createSyndicate`, and you resolve it with `factory.governorOf(vault)`
or `sherwood governor info --vault <vault>`. Protocol-level fees live on the shared
`ProtocolConfig` and are snapshotted into each proposal at propose time.

## Address resolution

The CLI resolves addresses at runtime from its 4663 book (`cli/src/lib/addresses.ts`).
Per-vault governors are not in the book — each vault's governor is resolved via
`factory.governorOf(vault)`.

When a core address the command needs is zero in the book, the CLI refuses with:
`Sherwood is not deployed on Robinhood Chain for this command yet. Retry after the mainnet deploy completes.`
