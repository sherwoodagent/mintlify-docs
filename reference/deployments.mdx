Sherwood v1 is live on **Robinhood Chain mainnet (chain 4663)**, an Arbitrum Orbit
L2. Run 1 of the deployment has been on chain since 2026-10-06. The CLI targets it by
default (`--chain robinhood-mainnet`), so no chain flag is needed.

Everything Sherwood needs lives on this one chain: the vault factory, the guardian
layer, the strategy templates, the canonical ERC-8004 IdentityRegistry, EAS, and the
WOOD token with its Uniswap pools.

| Chain | ID | Status | CLI flag |
|-------|----|--------|----------|
| Robinhood Chain mainnet | 4663 | Live | default (`--chain robinhood-mainnet`) |

<Note>
The factory runs with `ownerOnlyProposals = true` (only the vault owner proposes),
`depositsRestricted = true` (every vault takes deposits only from owner-approved
addresses), and a creation fee of 1,000,000 WOOD unless the creating wallet is
sponsored through the waitlist. Each flag is read live from the factory and can be
changed by the factory owner. See [Launch posture](/explanations/launch-posture).
</Note>

## $WOOD

$WOOD has one official contract on Robinhood Chain:
`0xF8BC08092C06dB6148114DCf82AF881F1085f92b`
([Blockscout](https://robinhoodchain.blockscout.com/token/0xF8BC08092C06dB6148114DCf82AF881F1085f92b),
[Uniswap](https://app.uniswap.org/explore/tokens/robinhood/0xF8BC08092C06dB6148114DCf82AF881F1085f92b)).
Treat any other contract named WOOD as unofficial.

WOOD trades against WETH on Uniswap. No CLI command buys WOOD; swap through the
router or the Uniswap app, quote first, and buy in tranches, because the pools are
shallow and a large buy moves the price.

Who needs WOOD: vault creators, for the 10,000 WOOD owner stake, the proposer bond on
every proposal, and the 1,000,000 WOOD creation fee when the wallet is not sponsored.
Depositors need none. The bond is about 2% of the deployed amount in WOOD at market.
See [Getting started](/guides/getting-started) for the reserve rule and
[Proposer bond](/explanations/proposer-bond) for how the bond is sized.

There is **no singleton `SyndicateGovernor`** (the book carries the zero address for
that key). Each vault's governor is a `BeaconProxy` the factory deploys at
`createSyndicate`, sharing one implementation through the `GovernorBeacon`, and is
resolved at runtime via `factory.governorOf(vault)`. Each vault also gets its own
`VaultWithdrawalQueue`, deployed by the factory. Protocol-level fee splits live on the
shared `ProtocolConfig`.

<Warning>
**Weekend feed gap.** The stock feeds heartbeat on US market days and go 52–55 hours
between updates every weekend, against the 26-hour freshness bound the Portfolio
strategy and the ledger enforce. A proposal holding stock tokens cannot execute,
settle or rebalance from about Saturday 18:40 UTC until Monday 00:00 UTC, and an
execution window that falls entirely inside that gap expires the proposal.
`sherwood sources get calendar` prints the live window. See
[Oracle staleness](/explanations/oracle-staleness).
</Warning>

## Deployment records

Per-chain deployment records are stored in `chains/{chainId}.json` in the protocol
repo (`4663.json` for Robinhood Chain). They hold the deployer, contract addresses,
token and feed addresses, and deployment metadata; the deploy scripts write them.

## Address resolution

The CLI resolves addresses at runtime in `cli/src/lib/addresses.ts`. Each address
family is a `Record<Network, ...>` map keyed by chain, with `robinhood-mainnet` as the
default network:

```
TOKENS()             → USDG / WETH / WOOD, stock tokens
UNISWAP()            → SwapRouter, QuoterV2, V3 factory, V4 pool manager, SwapAdapter
SHERWOOD()           → Factory, GovernorBeacon, ProtocolConfig, GuardianRegistry, StakedWood, TierRegistry, StrategyFactory
STRATEGY_TEMPLATES() → Portfolio, MorphoSupply, ConcentratedLiquidity, Launchpad, LighterPerp
LAUNCH_ADAPTERS()    → Sushi (Stonk zero)
STRATEGY_VENUES()    → Morpho Blue, Uniswap V3
CHAINLINK()          → per-token <SYM>_USD_FEED push feeds
EAS_CONTRACTS()      → EAS, SchemaRegistry
```

Per-vault governors are not in this table; each is resolved via `factory.governorOf(vault)`
(see `cli/src/lib/governor.ts`). Zero addresses mean a contract is not deployed on that
chain; commands that depend on one fail with a clear error at runtime.
